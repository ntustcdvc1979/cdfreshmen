# 大學星攻略 — 現場搶答系統

上台代表 + 台下學員的分組搶答遊戲。手機（直式）作答、主持人控制台、投影統計頁。
前端純靜態，架在 GitHub Pages；即時同步用 Firebase Realtime Database。

| 頁面 | 網址 | 誰用 |
|---|---|---|
| 玩家端 | `https://ntustcdvc1979.github.io/cdfreshmen/` | 學員手機 |
| 主持人控制台 | `.../host.html` | 主持人 |
| 投影統計頁 | `.../screen.html` | 投影幕 |
| 題目／組別後台 | `.../admin.html` | 出題的人 |
| 自我檢查 | `.../selftest.html` | 改過程式碼後開一下，看有沒有 FAIL |

## 一、遊戲怎麼玩

每組進場時要分工：**一位上台代表**，其餘是**台下學員**。

1. 主持人按「出題」→ 投影幕開始 **60 秒倒數**，配上逐漸升高的緊張音效。
2. **台下學員**在自己手機上選 A/B/C/D，隨時可以改。
3. **上台代表**手機上看得到自己這組的即時比例（選 A 幾 %、選 B 幾 %…），
   參考完之後選一個並按 **「確認送出」**（按下去直接送，不會再跳確認視窗）。
4. 任何一組確認，投影幕會有確認音效，那一組的格子亮起金色並顯示字母。
   （出題畫面是題目在上、各組格子在下；每一格左邊寫組別、右邊是該組的答案。）
5. 倒數歸零自動截止作答（不會自動公布答案，節奏還在主持人手上）。
6. 主持人按「公布答案」→ 投影幕**同時**出現金色大字正解與**答案說明**（文字 + 圖片，
   後台提供）。下方各組格子改成三欄：組名左、答案置中、✅／❌ 靠右。不用再按任何鍵。
7. 之後用 **→** / **←** 翻頁。頁序是：

   ```
   答案與說明 → 補充大圖（有填才有）→ 目前戰況（每 5 題才有）→ 全場作答分布
   ```

   頁尾會顯示左右兩邊各是什麼，不用記。換題會自動回到第一頁。
8. **每 5 題**（第 5、10、15…題）公布完答案後，翻頁會多出一頁「目前戰況」，
   顯示前 5 名。最後一題不插這頁，因為接著就是完整排行榜。
9. 全部跑完按「結束並公布排行榜」→ 投影幕進入**排行榜**：
   按空白鍵依序公布 **第三名 → 第二名 → 第一名**，第一名揭曉時會灑彩帶。
   只公布前三名。再按一次空白鍵看類別分析。

### 計分

| 條件 | 分數 |
|---|---|
| 上台代表答對 | +配分 |
| 台下學員答對率 **≥ 50%** | +配分 |

**兩筆分數互相獨立，各算各的** —— 代表沒送出、或送錯了，
台下學員只要答對率過半，那一分照樣拿得到。反之亦然。

**配分預設 1**，可以逐題調整（後台的「配分」欄位，1～99）。
一題每組最多拿到「配分 × 2」，排行榜就比總分。
同分時先比代表答對題數，再比學員答對人次。

配分不是 1 的題目，投影幕與學員手機都會在題號旁顯示 **+N** 金色徽章提醒大家。

**加倍轉盤**：主持人按「轉一次」，投影幕跳出轉盤轉出一組，那一組的**下一題**配分再 ×2
（代表答對與學員過半都加倍，滿分也跟著加倍，得分率才不會爆表）。
抽中的組在自己手機上會看到通知；投影幕頂部列會顯示「🎡 第 N 組 ×2」，該組的格子標紅框。

- 學員一個都沒作答的話，那 +1 不給（不會因為沒人答而白拿分）。
- 代表沒送出只是少了代表那一分，不會連帶影響學員那一分。
- 答對率剛好 50% 算過半，給分。
- **DEMO 題庫完全不計分**，可以放心拿來暖場。

## 二、先做這五件事（不做的話網站打不開資料）

### 1. 把 Firebase 設定放進 GitHub Secret

設定值不進版控 —— `assets/js/firebase-config.js` 已列在 `.gitignore`，
線上版本由 [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 在部署時產生。

GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**：

- Name：`FIREBASE_CONFIG`
- Secret：設定寫成 **一行 JSON**（鍵名要加雙引號），且**必須含 `databaseURL`**

本機測試另外複製一份：

```
copy assets\js\firebase-config.example.js assets\js\firebase-config.js
```

> ⚠️ 這只是讓設定值不出現在 git 紀錄裡。**它仍然會出現在部署後的網頁上** ——
> Firebase 前端 SDK 一定要把金鑰送到瀏覽器才能連線，任何人按 F12 都看得到。
> 安全性靠下面的第 2、3 步，不要靠藏金鑰。

### 2. 貼上資料庫安全性規則

Firebase 主控台 → **Realtime Database → 規則**，把
[`database.rules.json`](database.rules.json) 整份貼上並發布。這份規則做到：

- **正解不會外流**：`/answerKey/{題號}` 平常任何人都讀不到，只有主持人按下「公布答案」
  （寫入 `state/revealed/{題號} = true`）之後才變成可讀。開開發者工具也偷不到。
- **截止後不能補答**：只有 `state.phase === "open"` 且題號相符時才寫得進去。
- **代表的答案送出即定案**：規則要求 `!data.exists()`，同一題不能改第二次。
- **一組只有一位代表**：`/reps/{組}` 只有在空著、或本來就是你的時候才寫得進去。
- **只有那一組的代表讀得到那一組的學員作答**，別組看不到。
- **只有 `/admins` 名單上的 UID** 能改題目、改狀態、看全場原始資料。

### 3. 啟用 Google 登入（主持人）＋ 匿名登入（學員）

Firebase 主控台 → **Authentication → 登入方式**，兩個都要開：

- **Google** —— 主持人用（`host.html`、`admin.html`、`screen.html`）
- **匿名** —— 學員用

> **為什麼學員也需要登入？**
> 代表要讀「自己這一組」的學員比例，安全性規則必須認得出「你就是這組的代表」
> 才能放行。沒有身分的話，就只能把所有人的作答完全公開。匿名登入也順便讓
> 「一組只有一位代表」和「沒人能改別人的答案」變成規則層級的保證，不是靠前端自律。

再到 **Authentication → 設定 → 授權網域**，確認清單裡有 **`ntustcdvc1979.github.io`**。
少了它，線上版按登入會出現 `auth/unauthorized-domain`。

> ⚠️ **更正之前的說法**：因為要用匿名登入，**「啟用建立帳戶」不能關掉**
> （匿名登入本身就算建立帳戶）。權限邊界完全靠 `/admins` 白名單 ——
> 匿名使用者拿不到任何主持人權限，這一點在規則裡是硬的。

### 4. 把自己的 UID 加進主持人白名單

**這一步不能跳過。** 任何人都有 Google 帳號，所以規則看的不是「有沒有登入」，
而是「這個 UID 在不在 `/admins` 名單上」。

1. 開 `host.html`，用你的 Gmail 登入 —— **第一次會被擋下來，這是正常的**，
   畫面上會直接顯示你的 UID，複製它。
2. Firebase 主控台 → **Realtime Database → 資料**，在根目錄手動新增：

   ```
   admins
     └─ 剛才複製的UID :  true      （型別選 boolean）
   ```

3. 回到 `host.html` 重新登入，就進得去了。

要多一位主持人的話，請對方登入一次拿到 UID，重複第 2 步即可。

### 5.（建議）限制 API 金鑰的來源網域

Google Cloud Console → **API 和服務 → 憑證 → 你的瀏覽器金鑰 → 應用程式限制**
選「HTTP 參照網址」，加入 `ntustcdvc1979.github.io/*`。

## 四、活動前準備

1. 開 `admin.html` 登入。
2. **組別**：按「快速建立 1～N 組」一次建好，或逐一新增、改名、排序。
3. **題目**：上方先選「正在編輯哪個題庫」（正式 / DEMO），再新增題目。每題可以填：
   - 題幹、A～D 選項、正解
   - **類別**（六個主視覺項目之一，見下一節）
   - **配分**（預設 1）—— 不是 1 的話投影幕會在題號旁顯示 +N
   - **說明排版**（公布答案時跟正解一起出現在投影幕）——
     一格一格自己排，每格可以是**小標題／文字／圖片／影片**，
     並選擇**大小 1～5**、**靠左／置中／靠右**，還能上下搬動與刪除。
     寬度有三種：

     | 寬度 | 效果 |
     | --- | --- |
     | 整行 | 自己獨佔一行 |
     | 半行 | 兩格並排成左右兩欄，中間留空隙 |
     | 自動寬（緊貼並排） | 只佔內容需要的寬，**連續**的自動寬排在同一列，中間只留一點點縫 |

     所以兩張圖想並排成 A B（而不是中間開天窗的 _A_ _B_），
     就把兩格都選「自動寬」，再用對齊決定這一對要靠左、置中還是靠右
     （整列的對齊看這一列第一格）。下方有 16:9 的即時預覽，所見即所得。

     兩個要記得的行為：

     - **整格說明只有一張圖（或一段影片）時，它會自動佔滿整個說明區**，
       這時候「大小」就不影響了 —— 想讓圖小一點，就再加一格文字。
     - **影片**格填 YouTube／Vimeo 網址會轉成內嵌播放器（`youtu.be`、
       `watch?v=`、`shorts/` 都認得），填 `assets/video/檔名.mp4` 之類的路徑
       則用瀏覽器內建播放器。**內嵌的 YouTube 需要現場有網路**，
       場地網路沒把握的話請改放 mp4 檔案進 `assets/video/`。
   - **整頁大圖／影片**（選填）—— 自己獨立一頁、佔滿整個投影畫面，
     適合流程圖、對照表這種需要看細節的東西。
     這一欄填影片網址就會變成整頁播影片（YouTube／Vimeo 或 `.mp4`
     之類的檔案都可以，系統看網址自己判斷）：

     - **只播一次，播完就停在最後一格，不會重播**
     - 進到這一頁自動開始播，播的時候講解的背景音樂會自動讓開，
       翻到下一頁再接回來
     - 資料更新造成的重畫不會把影片跳回第一幀
     - 本機影片檔放 `assets/video/`；YouTube 需要現場有網路，
       而且瀏覽器可能擋掉自動播放，這時主持人按一下播放鍵就好

   - **說明音檔**（選填）—— 跟整頁大圖是**同一頁**：大圖鋪滿畫面、音檔在底下播，
     適合放旁白或一段訪談。

     - **只播一次，不會重播**；翻到別頁就停，翻回來才重新開始
     - 資料更新造成的重畫不會把音檔跳回開頭
     - 播的時候講解的背景音樂會自動讓開，畫面下方會有「🔊 說明音檔播放中」
     - **沒填整頁大圖、只填音檔也可以** —— 那一頁就純粹放音檔
     - 整頁大圖填的是**影片**時，影片自己有聲音，說明音檔會略過不播
     - 主持人按「上／下課鐘聲」或「健康操」時，說明音檔會讓開
     - 檔案放 `assets/audio/`，這裡填 `assets/audio/檔名.mp3`；
       也可以貼外部音檔直連網址

   **影片與音檔預載**：投影幕一開，就會在背景把這一場題目用到的**本機**影片與音檔
   （`assets/video/`、`assets/audio/` 底下那些）依序抓下來放著，真的翻到那一頁才不會邊播邊等。
   一次只抓一支，不會跟正在播的開場影片搶頻寬。
   所以**開場前早點把投影頁打開**，讓它有時間把影片抓完。
   想確認進度就在投影頁按 F12 打 `__preload()`，會列出每支影片的狀態
   （`waiting` 排隊中／`loading` 抓取中／`ready` 抓好了／`slow` 太慢先跳過）。
   YouTube／Vimeo 是外部嵌入，沒辦法預載 —— 在意卡頓就把影片放成本機檔。
4. 也可以用最下面的「批次貼上」一次匯入到目前題庫 —— 一行一題，用 `|` 分隔：

   ```
   題幹 | A選項 | B選項 | C選項 | D選項 | 正解字母 | 類別
   ```

   最後的類別可省略。只有兩個選項就少寫兩欄：`題幹|甲|乙|A|親善大使`。
   例如：

   ```
   大學的「必修」和「選修」差在哪？|必修可以不修|必修沒修完不能畢業|選修不算學分|兩個一樣|B|時間管理大師
   遇到室友作息完全相反，最好的第一步是？|直接搬走|忍到學期末|找時間好好溝通|請家長出面|C|人際網絡高手
   ```

   說明排版要匯入後逐題編輯（批次格式塞不下）。
5. 圖片（說明區塊裡的圖、整頁大圖）都是選填。放法有兩種：
   - 貼一個外部圖片直連網址
   - 把圖片檔放進 repo 的 `assets/img/explain/`，這裡填 `assets/img/explain/檔名.webp`
   （後台會即時預覽，貼錯會看到破圖；投影時載不出來會顯示提示文字而不是空白）

   站內圖片一律存成 **.webp**（同樣畫質、檔案小很多，投影機和手機都載得比較快）。
   轉檔：`cwebp -q 92 -m 6 -alpha_q 100 原圖.png -o 圖.webp`，
   來源是 jpg 就用 `-q 85`（jpg 已經壓過，再用高品質重壓反而會變大）。
   舊題目如果還填著 `.png` / `.jpg` 也不用改 —— 系統會自動先找同名的
   `.webp`，找不到才用你填的原路徑。
   圖片的長寬比不用管，橫的、直的、超長的表格都會自動縮到剛好塞滿畫面。
6. 用 `host.html` 的「顯示玩家端 QR Code」把 QR 存下來貼到 Canva 簡報。
7. **先用 DEMO 題庫實際跑一輪**，確認代表都搶到位子、音效有出來。
8. 測完按 host.html 的 **「清除所有作答紀錄」**。

## 五、現場操作

### 主持人控制台 `host.html`

| 按鈕 | 做什麼 |
|---|---|
| **題庫** | 切換正式 / DEMO。切換會回到待機 |
| **▶ 出題／開始倒數** | 推題目給所有人，投影幕開始倒數 |
| **■ 提前截止** | 不等倒數結束就鎖住，**不公布答案** |
| **🎉 公布答案** | 算好統計並解鎖正解 |
| **下一題 →** | 直接切下一題並重新開始倒數 |
| **🏆 結束並公布排行榜** | 產生總分排名 |
| **◀ 上一頁 / 下一頁 ▶** | 遠端翻投影幕的頁，跟在投影機那台按 ←／→ 一樣。旁邊的標籤顯示投影幕現在停在第幾頁 |
| **🎡 轉一次** | 投影幕跳出加倍轉盤，抽一組出來，該組**下一題**配分 ×2。轉的時候只有轉盤的音樂，停下時放 `wow.m4a`，放完才接回原本的背景音樂。轉完會留在畫面上，按「出題／下一題」才收掉（投影幕按 Esc 也可以手動關）|
| **取消加倍** | 抽完後想反悔就按這個 |
| **🔔 上／下課鐘聲** | 投影幕放鐘聲音檔。放到一半想停就再按一次同一顆 |
| **🤸 健康操** | 投影幕放健康操音樂，同樣再按一次可以停 |
| **⟲ 清除本題作答** | 這一題重來（代表答案＋學員作答都清掉） |

控制台還看得到：各組代表已確認的答案分布、台下學員的整場分布、即時排行榜、
類別分析、以及**各組代表名單**（有人手機壞掉可以按「釋放」讓別人重新接手）。

**投影設定**：倒數秒數、格子欄數（0 = 自動）、以及
**「鎖定前就在投影幕顯示各組選的字母」**。取消勾選的話，鎖定前只顯示
「已確認 ✓ / 未確認 ···」，公布答案時才翻出字母 —— 可以避免後決定的組別
看著別組的答案下注。預設是開著的（張力比較夠）。

**投影幕翻頁**：主持人不用跑到投影機那台去按鍵盤 —— 控制台的
「◀ 上一頁 / 下一頁 ▶」跟在投影機上按 ←／→ 是同一條路，開場五頁、
公布答案的說明頁、排行榜依序揭曉名次都翻得動。卡片上的標籤會顯示
投影幕現在停在第幾頁（例如「開場 3/5　主視覺」），不用盲按。
出題與截止中投影幕只有一頁，這兩顆會自動變灰。

**投影幕播放**：「🔔 上／下課鐘聲」與「🤸 健康操」把音檔放在**投影幕**上
（控制台自己不出聲，主持人的手機不會跟著響）。放的時候現場的背景音樂會先收掉，
放完自動接回來；卡片上的標籤會顯示現在正在放什麼，再按一次同一顆就是停。
投影頁要先按過「開啟音效」才出得了聲。

### 投影頁 `screen.html`

**待機時是五頁開場**，用 **→** / **←** 翻：

| 頁 | 內容 |
|---|---|
| 1 | **黑畫面** —— 整片全黑。投影機先開著暖機、台下什麼都看不到，等主持人按 → 才開場 |
| 2 | **開場影片** —— `assets/video/themes.mp4` 滿版鋪滿整個投影畫面（連頂部列與頁尾都收起來）。影片是循環播的，按 → 就往下一頁 |
| 3 | **主視覺** —— `assets/img/hero.webp`（大學星攻略 — 創造我的大學價值）滿版靜態圖，主持人開場就是對著這張講 |
| 4 | **遊戲規則** —— 規則條列 + 兩支手機示意圖（台下學員／上台代表各一），用學員端真正的元件樣式組出來，跟他們手上看到的一致。後台填了自己的規則圖就換成那張 |
| 5 | **掃碼進場** —— 玩家端 QR Code，旁邊即時顯示各組代表就位狀況。有人選了「上台代表」那一格就亮綠並發出報到音 |

- 第一次開會要求按一下「開啟音效」——瀏覽器規定必須有使用者手勢才能出聲。
  按完再按 **F11** 進全螢幕。
- **公布答案階段**：正解與說明會一起出現；`→` / `←` 翻頁，頁序是
  「答案與說明 → 補充說明（整頁大圖／影片／音檔，有填才有）→ 目前戰況（每 5 題才有）→ 全場作答分布」，
  頁尾會顯示左右各是什麼。
- **最終畫面**：排行榜。`空白鍵` 依序公布第三名 → 第二名 → 第一名（第一名會灑彩帶），
  再按一次進入類別分析。`←` 可以倒回上一步重播。**只公布前三名。**
- 投影幕不顯示題庫名稱（正式／DEMO），觀眾席不需要知道。
- 上面每一種翻頁，主持人在控制台按「◀ 上一頁 / 下一頁 ▶」也翻得動 ——
  不用跑到投影機那台去按鍵盤。兩邊走的是同一段程式，行為一定一致。
- 需要主持人身分才讀得到統計。同一個瀏覽器先開 `host.html` 登入過就會自動沿用。

### 音效

全部用 Web Audio 即時合成，沒有音檔要準備、也沒有版權問題：

| 時機 | 聲音 |
|---|---|
| 開放作答 | **倒數 BGM**：A 小調四小節循環（Am→Am→F→E），16 分音符的低音固定音型 + 大鼓 + hi-hat，四小節結尾有上升噪音。速度從 104 BPM 一路推到 168 BPM，濾波與音量同步往上開 |
| 剩 10 秒起 | 每秒加一記尖銳重音，剩 5 秒更高更亮（BGM 本身有節拍，所以前面不加滴答） |
| 有一組代表就位 | 輕快的兩音報到聲（開場掃碼頁最需要這個回饋） |
| 轉盤轉動 | 每經過一格「答」一聲，越轉越慢就變成一串答答答 |
| 轉盤停下 | 放 `assets/audio/wow.m4a`（三音上揚同時墊著）。**放完才把原本的背景音樂接回來** —— 這時轉盤還留在畫面上 |
| 任一組確認 | 明亮的兩音上揚 |
| 時間到 | 乾脆的一記撞擊：低頻衝擊 + 金屬鑼聲 + 小調和弦收尾（刻意不用往下滑音，那聽起來像在嘲笑人） |
| 公布答案 | 上揚和弦 |
| 公布排行榜 | 五音勝利音 |
| 主持人按「上／下課鐘聲」／「健康操」 | 放 `assets/audio/bell.m4a` ／ `lucy.m4a`，其他背景音樂先收掉，放完接回來 |
| 補充說明那一頁有說明音檔 | 放後台填的音檔，只播一次；講解背景音樂先讓開，翻走就停 |

**轉盤的聲音是獨佔的**：從按下「轉一次」到那一聲 `wow.m4a` 放完為止，
其他背景音樂一律不會插進來（連公布答案、翻頁重畫也不會）。
`wow.m4a` 放完才接回原本該放的那首。

> `assets/audio/wow.m4a` **要自己放進去**。沒放的話轉盤停下就沒有那一聲，
> 背景音樂會立刻接回來，其他都照常 —— 不會卡住也不會沒聲音。

BGM 用「預先排程」送出音符，所以主執行緒卡頓不會讓節拍飄掉。
想換曲風就改 [`assets/js/sounds.js`](assets/js/sounds.js) 最上面的
`CHORD_ROOTS`（和弦進行）、`BASS_PATTERN`（低音音型）與 `bgmTempo()`（速度曲線）。

畫面同步的效果：剩 20 秒開始有掃描光掠過，剩 5 秒整個畫面微震、倒數圈轉紅脈動。

## 六、題目類別與強項分析

每題可歸到六個類別之一，對應主視覺上那六張卡片：

| 類別 | 顏色 |
|---|---|
| 人際網絡高手 | 桃紅 |
| 親善大使 | 金黃 |
| 美食小當家 | 綠 |
| 時間管理大師 | 橘 |
| 情緒管理大師 | 紫 |
| 團隊領航員 | 藍 |

要增減或改名，改 [`assets/js/common.js`](assets/js/common.js) 最上面的 `CATEGORIES`。
題目是用 `id` 存的，改 `name` 不會弄壞既有資料。

分析結果是**一張「組別 × 類別」的得分率矩陣**，同時回答兩個問題：

- **金色格子**＝該類別得分率最高的組（直的看：這個類別哪一組最強）
- **藍框格子**＝該組得分率最高的類別（橫的看：這一組最擅長什麼）
- `–` 代表那個類別還沒有題目公布

`host.html` 另外把兩個答案列成清單；`screen.html` 最終畫面按空白鍵可以切過去；
學員手機在結束畫面也會看到自己那組的最強項目。只計算**已公布的正式題目**。

## 八、資料庫結構

```
/admins/{uid}                  true                     ← 主持人白名單，只能從主控台改
/config/groups/{gid}           { name, order }
/config/intro                  { rulesImg }             ← 規則頁的圖（選填）
/questions/{qid}               { order, text, a,b,c,d, cat, list, pts,
                                 exText, exImg, exImgFull, exAudio }
                                                        ← 公開可讀，不含正解
/answerKey/{qid}               "A"                      ← 只有公布後才可讀
/state                         { phase, list, qid, openedAt, limitSec,
                                 gridCols, showRepLetters, revealed:{qid:true},
                                 pendingDouble, wheel:{id,gid}, cue:{id,kind},
                                 nav:{id,dir}, screenPage }
/reps/{gid}                    { uid, at }              ← 該組代表，一組一位
/repAnswers/{qid}/{gid}        { c, uid, t }            ← 代表確認後的答案，不可改
/responses/{qid}/{gid}/{uid}   { c, t }                 ← 台下學員，只有本組代表讀得到
/stats/{qid}                   { A,B,C,D,total,key, rep:{…} }
/doubles/{qid}                 gid                      ← 轉盤抽中、該題 ×2 的組
/leaderboard                   { updatedAt, rows:[…] }
```

`phase`：`idle` 待機、`open` 開放作答、`locked` 截止未公布、`reveal` 已公布、`final` 排行榜。
`list`：`main` 正式題、`demo` 練習題。
`cue`：主持人要投影幕放哪個音檔 —— `bell` 上／下課鐘聲、`exercise` 健康操。
投影頁放完會把它清成 `null`，控制台的按鈕就跳回「播放」。
`nav`：控制台按翻頁時寫 `{ id, dir }`，投影頁看到新的 id 就翻一頁（`dir` 是 +1／-1）。
`screenPage`：反過來由投影頁寫，讓控制台知道現在停在第幾頁。

## 九、已知限制

- **Firebase 金鑰一定是公開的**，藏不住。安全性靠資料庫規則 + `/admins` 白名單。
- 因為用匿名登入，**不能關閉「啟用建立帳戶」**。匿名帳號拿不到任何主持人權限。
- 代表身分綁在**那一支手機**上。清掉瀏覽器資料或換手機就要主持人在控制台
  「釋放」該組代表位置，再重新選一次。
- 台下學員以「一支手機一票」計算，沒有真實身分驗證。同一個人用兩支手機會算兩票 ——
  對迎新活動的規模是可接受的。
- 主持人登入用 Google 彈出視窗。被瀏覽器擋掉時會自動改成整頁轉址，但 iOS Safari
  對轉址式登入限制較嚴 —— 主持人請用電腦版 Chrome / Edge 並允許彈出視窗。
- 免費方案的 Realtime Database 同時連線上限 100 人。超過要升級 Blaze（按量計費，
  這種規模幾乎不會產生費用）。
- 倒數自動截止是由 **`host.html` 負責寫入**的。控制台整場都要開著，關掉的話
  時間到不會自動鎖，要手動按「提前截止」。
